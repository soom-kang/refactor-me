## RM-QA-001

- **Summary:** Reject malformed locked validation input and prevent zero-check success
- **Type / Owner:** Bug / CLI validation maintainer
- **Priority / Severity:** P1 / High

### Current State (QA baseline)

[DiscoverCommands](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/workspace/validate.go#L325)는 기존 `commands.json`의 read/parse 오류를 반환하지 않고 자동 discovery로 전환합니다. `locked:true`에서 `area`가 누락되면 `Discovery.Areas`만 `"."`으로 보정하고 `Command.Area`는 비워 둡니다. [RunLadder](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/workspace/validate.go#L655)는 빈 area 명령을 건너뛰고 `OK=true`를 반환합니다. controller는 이 결과로 다음 단계에 진행할 수 있습니다.

### Evidence / Reproduction

`[Verified]` 임시 module에서 실제 discovery, baseline과 ladder를 호출했습니다. 기존 Makefile이 있는 repository의 malformed 입력은 `error=<nil> locked=false commands=1`을 반환했습니다.

```json
{"locked":true,"commands":[
```

다음 입력은 baseline 1개를 통과한 뒤 `changed=["a.go"]`의 ladder 검사를 0개 실행했습니다.

```json
{"locked":true,"commands":[{"id":"check","tier":"T1","argv":["/usr/bin/true"],"cwd":"."}]}
```

```text
areas=["."] baseline_usable=true baseline_checks=1 ladder_ok=true ladder_checks=0
```

계약은 [Reference의 locked command 형식](../../tool/README.md#validation-commands)입니다. provider review와 publication까지의 전체 실행은 재현하지 않았습니다. [candidate validation 소비 경로](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/controller/candidate.go#L400)는 소스로 확인했습니다.

### Expected State

명시적으로 존재하는 검증 설정이 읽히지 않거나 유효하지 않으면 시작 전에 오류를 반환합니다. locked 명령을 동일한 정규화 결과로 baseline과 candidate validation에 사용합니다. 필요한 검사가 누락되면 성공으로 기록하지 않습니다.

### Acceptance Criteria

1. 기존 파일의 read/parse 오류를 key/path와 함께 반환하고 자동 discovery로 바꾸지 않습니다. 파일이 없는 정상 경우는 기존 discovery를 유지합니다.
2. `locked:true`의 고유 ID, tier, argv, area와 cwd를 검증합니다. area 기본값을 지원한다면 `Command.Area`에도 반영합니다.
3. 위 누락 입력은 거부하거나 정규화 후 candidate check 1개를 실행합니다. 0-check 성공을 재현할 수 없어야 합니다.
4. 정상 root/하위 area, baseline RED 비교와 의도된 skipped status의 기존 계약은 유지합니다.
5. 기존 workspace/controller tests에 필요한 사례만 추가합니다. 별도 validation framework는 만들지 않습니다.

### Resolution — 2026-10-12

Locked 파일의 read/parse/type 오류와 빈 명령·중복 ID·tier·argv·경로·timeout 범위를 거부합니다. 누락된 area/cwd를 실제 명령의 `.`으로 정규화하고, 실행된 check가 없으면 `VALIDATION_UNRUNNABLE`입니다. Doctor는 provider/worktree 준비 전에 설정을 검사합니다.

검증: `TestContractLockedDiscoveryRejectsInvalidInput`, `TestContractLockedAreaNormalizationAndEmptyLadder`, `TestDoctorRejectsInvalidLockedConfigurationBeforePreparation`. 개별 regression은 PASS이며 전체 통합 검증은 [해결 기록](2026-10-12-remediation.md)에서 확인합니다. 상태는 local implementation에 해당하며 공개 Beta.6 반영을 뜻하지 않습니다.

### Evidence / Reproduction

`[Verified]` source의 `node_modules`를 외부 fixture directory에 연결한 뒤 실제 `runner.hydrate()`를 호출했습니다. 복사된 worktree의 `node_modules/marker`에 임시 값을 쓰자 외부 marker가 변경됐습니다: `external_mutation=true`. 쓰기는 validation process를 모사했습니다. 실제 dependency, provider 또는 `.env` 값은 사용하지 않았습니다.

### Expected State

기본 hydration이 worktree 밖으로 향하는 writable link를 재생성하지 않습니다. 안전한 복사가 불가능하면 해당 입력을 건너뛰고 진단을 남깁니다. materialization이나 내부 counterpart 재연결의 선택은 구현 전에 호환성을 검토합니다.

### Acceptance Criteria

1. 복사 대상과 복사된 tree 내부 link의 실제 경로를 확인합니다.
2. 외부 fixture marker는 동일 재현 후에도 바뀌지 않습니다.
3. 정상 regular file/directory 복사는 유지합니다. 내부 link의 지원 조건을 명시합니다.
4. 거부/생략에는 상대 경로와 원인만 표시하고 secret value를 출력하지 않습니다.
5. pnpm/shared dependency layout 등 기존 사용 사례를 확인한 뒤 복사 정책을 정합니다. 검증 command 자체의 OS sandbox를 도입했다고 주장하지 않습니다.

### Resolution — 2026-10-12

사용자가 선택한 전체 입력 생략 정책을 적용했습니다. 복사 전후에 absolute/outside/dangling link를 확인하며 새 incomplete/unsafe 입력만 `os.Root`로 정리합니다. 기존 destination과 source를 보존하고 안전한 relative 내부 link는 복사합니다.

검증: `TestHydrationSkipsUnsafeInputsAndCopiesInternalLinks`. 개별 regression은 PASS이며 전체 통합 검증은 [해결 기록](2026-10-12-remediation.md)에서 확인합니다. 상태는 local implementation에 해당하며 공개 Beta.6 반영을 뜻하지 않습니다.

- **Type / Owner:** Bug / CLI configuration maintainer
- **Priority / Severity:** P2 / Medium

### Current State (QA baseline)

[LoadConfig](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/surface/config.go#L68)의 `object()`는 잘못된 JSON type을 빈 object로 바꾸고, [readPolicy](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/controller/policy.go#L29)는 잘못된 boolean/number를 defaults로 대체합니다. [configuredMaxMinutes](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/surface/duration.go#L28)도 잘못된 type을 조용히 무시합니다. 일부 숫자만 범위를 확인하므로 `max_audit_candidates=-1`은 [audit slice](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/controller/cycles.go#L329)에서 panic을 일으킵니다. 두 관찰은 알려진 설정의 불완전한 입력 검증이라는 같은 원인으로 묶었습니다.

### Evidence / Reproduction

`[Verified]` 실제 loader와 policy 함수에 다음 입력을 주면 오류 없이 characterization/review는 `true`, cycles는 `25`, 시간은 `180`으로 해석합니다.

```json
{"schema_version":2,"policy":{"auto_characterization":"false","cross_provider_review":"false","max_cycles":"1","max_wall_clock_min":"1"}}
```

`{"schema_version":2,"policy":"not-an-object"}`도 오류 없이 기본 policy가 됩니다. 별도의 public CLI 재현에서는 fake Codex가 유효한 빈 audit JSON을 반환하고 `max_audit_candidates=-1`을 설정하자 `runtime error: slice bounds out of range [:-1]`로 정상 report 경로를 우회했습니다.

### Expected State

알려진 설정 key의 type과 지원 범위를 시작 전에 검증합니다. 설정 생략과 malformed 값을 구분하고 unknown extension key 보존은 유지합니다.

### Acceptance Criteria

1. 알려진 object/boolean/string/number 오류에 정확한 key와 기대 type을 표시합니다.
2. 음수 audit cap과 duration overflow 등을 provider/worktree 준비 전에 거부합니다. 각 필드의 정수 및 0 허용 의미를 기존 호환성과 함께 명시합니다.
3. defaults는 생략된 정상 설정에만 적용하고 문자열 `"false"`나 `"1"`을 조용히 대체하지 않습니다.
4. 위 입력은 명시적 오류로 끝나고 유효한 설정, extension key와 config bytes는 보존됩니다.
5. 기존 surface/policy tests를 보완하며 production dependency를 추가하지 않습니다.

### Resolution — 2026-10-12

설정 loader와 직접 policy 소비 경계에서 알려진 type, 정수, 범위, duration/native-int overflow와 원본 JSON precision을 검증합니다. 생략된 defaults, extension key와 기존 0 의미는 보존합니다.

검증: `TestKnownConfigValidationBeforeRunPreservesInput`, `TestKnownConfigValidationKeepsZeroDefaultsAndExtensions`, `TestConfiguredMaxMinutesRejectsMalformedValues`, `TestContractPolicyRejectsMalformedKnownSettings`. 개별 regression은 PASS이며 전체 통합 검증은 [해결 기록](2026-10-12-remediation.md)에서 확인합니다. 상태는 local implementation에 해당하며 공개 Beta.6 반영을 뜻하지 않습니다.

## RM-QA-005

- **Summary:** Recheck source invariants immediately before result publication
- **Type / Owner:** Bug / Controller maintainer
- **Priority / Severity:** P2 / Medium

### Current State (QA baseline)

[gate](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/workspace/gate.go#L273)는 source HEAD와 fingerprint를 확인합니다. 그 뒤 [commit](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/controller/candidate.go#L496)과 [publish](https://github.com/soom-kang/refactor-me/blob/0229e141d59cf6b248c422ac5b4dbb482fd37813/tool/go/internal/controller/cycles.go#L402)는 reviewed worktree tree, Skills와 result ref CAS를 확인하지만 source 상태를 다시 검사하지 않습니다. QA 전 Workflow는 publication 조건으로 source unchanged를 설명했습니다.

### Evidence / Reproduction

`[Verified]` owned disposable worktree의 DEAD_CODE 변경으로 gate PASS를 얻고, 이후 원본 tracked file을 수정한 뒤 실제 `runner.commit()`을 호출했습니다.

```text
gate=PASS source_changed=true commit_error=<nil> result_branch_exists=true
```

원본 변경은 동시 사용자 편집을 모사했습니다. CLI에 의한 원본 수정 또는 자동 merge의 데이터 손실을 입증한 것은 아닙니다. 최종 source invariant에 대한 확인이 누락된 것입니다.

### Expected State

마지막 쓰기/publication 경계에서 source HEAD와 fingerprint를 다시 확인합니다. drift를 발견하면 원본을 되돌리지 않고 안전 정지와 근거를 남깁니다.

### Acceptance Criteria

1. gate 이후 validation/review/commit hook 구간의 source file 변경과 HEAD 이동을 검출합니다.
2. 실패 시 `HALTED_UNSAFE`, 기존 result ref와 보존 worktree를 유지합니다. 변경된 원본에는 rollback을 적용하지 않습니다.
3. characterization publication에도 같은 경계를 적용합니다.
4. 정상 source 불변과 기존 CAS/tree 검사 동작은 유지합니다. 완전한 filesystem 동시성 차단을 주장하지 않고 검사 시점을 명시합니다.

### Resolution — 2026-10-12

Approved commit 전과 hook/Skill 확인 이후 publication CAS 직전에 source HEAD/fingerprint를 다시 확인합니다. Drift는 `HALTED_UNSAFE`이며 원본과 기존 result ref를 되돌리지 않습니다. Characterization publication도 같은 검사에 연결합니다.

검증: `TestSourceInvariantBlocksPublicationAfterGate`, `TestCharacterizationSourceInvariantAfterValidation`. 개별 regression은 PASS이며 전체 통합 검증은 [해결 기록](2026-10-12-remediation.md)에서 확인합니다. 상태는 local implementation에 해당하며 공개 Beta.6 반영을 뜻하지 않습니다.

### Evidence / Reproduction

`[Verified]` public CLI의 fake provider 첫 호출은 `first-failed` stdout과 `first-attempt-error` stderr 후 exit 1, 두 번째는 `second-success`와 유효한 audit 후 exit 0으로 설정했습니다. calls는 2인데 저장 stdout에는 두 번째만 남고 stderr에는 첫 번째 오류가 남았습니다.

### Expected State
