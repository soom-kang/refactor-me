## 반증 검토와 제외한 주장

1. 기존 PhaseEvidence 전파, characterization gate, 선언 삭제의 `os.OpenRoot`, reviewed-tree commit 검사와 owned-worktree rollback은 현 소스에 있습니다. 이전 문제를 신규 결함으로 다시 등록하지 않았습니다.
2. Source drift 재현은 gate 이후 동시 사용자 편집을 모사했습니다. CLI가 원본 tracked source를 직접 썼다는 증거로 표현하지 않았습니다.
3. 취소 재현은 validation의 parent context 취소입니다. accepted commit 소실이나 전체 CLI SIGINT 경로를 재현한 것으로 확대하지 않았습니다.
4. 현재 Beta.6 tag는 annotated tag입니다. 미래 generator의 tag gate 누락을 현재 Beta.6 설치 실패로 표현하지 않았습니다.
5. Git 환경변수 상속, state TOCTOU, 새 dependency, 광범위한 구조 재설계, 모든 release에 race/lint/audit를 강제하는 제안은 입증된 신규 결함으로 채택하지 않았습니다.

## 판단, 합의와 repository 상태

`sharpen-assess` 기준으로 이번 문서 변경의 위험은 **low**입니다. application 실행 자체의 노출은 source/worktree, 검증 command와 provider 비용을 포함하므로 문서 변경 위험과 분리합니다. cross-domain gate 판단에는 `frontier / thorough` 수준의 검토가 적합하되 model/effort 설정은 변경하지 않았습니다. 강한 추론을 테스트나 실제 설치 증거의 대체물로 취급하지 않았습니다.

사용자는 이번 QA에서 **`L3_CRITICAL`은 `allowed_risks`에 추가해도 항상 차단**하는 계약을 선택했습니다. [RM-QA-012](2026-10-12-tickets.md#rm-qa-012)의 Expected State는 이 합의를 반영합니다. 런타임의 차단은 아직 구현하지 않았습니다.

- `[Verified]`는 현 소스, 로컬 반례 또는 조회한 원본 기록으로 확인한 관찰입니다. 실제 provider 빈도와 현재 설치 경험은 포함하지 않습니다.
- `[Inference]` 외부 cwd/link에서 쓰기를 수행하는 검증 명령은 원본이나 shared cache를 변경할 수 있습니다. 외부 fixture 변경은 재현했지만 실제 사용자 데이터 변경은 관찰하지 않았습니다.
- `[Assumption]` 요청은 QA와 관련 문서 갱신입니다. 티켓의 구현, 외부 JIRA 등록, 공개 release 변경까지 포함한다고 해석하지 않았습니다.
- `[Unverified]` known vulnerability DB 결과, upstream provider에서 nonzero success payload가 발생하는 빈도와 전체 CLI signal 경험은 미확인입니다.
